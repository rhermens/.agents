# Hermes _SANE_PATH missing NixOS system directories

## Origin

Discovered while debugging a `Cleanup notes` cron job on NixOS that kept
failing or exhausting its tool-call budget without applying edits.

## The bug

Hermes Agent's terminal tool builds PATH from the agent process's PATH plus
a static fallback (`_SANE_PATH` in `tools/environments/local.py`). The
original `_SANE_PATH` only included macOS/Homebrew and standard FHS Linux
dirs:

```python
_SANE_PATH = (
    "/opt/homebrew/bin:/opt/homebrew/sbin:"
    "/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
)
```

On NixOS, `ls`, `find`, `head`, `grep`, `rg` live in
`/run/current-system/sw/bin`, which was absent from both the cron process's
PATH and the `_SANE_PATH` fallback.

## Why search_files broke too

The `search_files` tool (in `tools/file_operations.py`) internally pipes
ripgrep output through `head -n <limit>`:

```python
cmd_parts.extend(["|", "head", "-n", str(fetch_limit)])
```

Since `head` was not on PATH, every `search_files` call returned:

```
(eval):1: command not found: head
```

instead of search results. This affected both filename and content searches.

## How it manifested in cron runs

The cron agent (running `minimax/minimax-m3` or `openai/gpt-oss-120b`)
would:

1. Try `ls -la /path | head -50` → `command not found: ls` + `command not found: head`
2. Try `search_files` → `command not found: head`
3. Try `find /path | head -50` → `command not found: find` + `command not found: head`
4. Try `/bin/ls` → `no such file or directory: /bin/ls` (NixOS has no `/bin/ls`)
5. Eventually fall back to `python3 << 'EOF'` heredocs
6. Run out of tool-call budget before completing the actual task

Each run wasted 4–7 tool calls on PATH diagnostics.

## The fix — config approach (preferred)

Set `terminal.shell_init_files` in `~/.hermes/config.yaml`:

```yaml
terminal:
  shell_init_files:
    - /etc/set-environment
```

`/etc/set-environment` is generated by NixOS and exports the full system
PATH. Hermes's session snapshot sources this at init, so every subsequent
command inherits the correct PATH. This is the documented approach from the
Hermes FAQ and survives upgrades.

**Important:** when `shell_init_files` is set, the default `~/.bashrc`
auto-source is NOT added. Include it explicitly if needed:

```yaml
terminal:
  shell_init_files:
    - /etc/set-environment
    - ~/.bashrc
```

## The fix — source patch (alternative)

If the config approach is unavailable, patch
`_append_missing_sane_path_entries()` in `tools/environments/local.py`:

```python
# After the existing _SANE_PATH loop, before the return:
import os as _os
for nix_dir in (
    "/run/current-system/sw/bin",
    "/etc/profiles/per-user/" + _os.environ.get("USER", ""),
    "/nix/var/nix/profiles/default/bin",
):
    if nix_dir and nix_dir not in seen and _os.path.isdir(nix_dir):
        ordered_entries.append(nix_dir)
```

The `isdir` guard ensures this is a no-op on non-NixOS systems. This patch
will be lost on Hermes updates — prefer the config approach above.

## How the config fix was validated

After setting `shell_init_files: [/etc/set-environment]`:

- `search_files` (previously returning `(eval):1: command not found: head`)
  now returns results correctly in the interactive session.
- `bash -l -c 'echo $PATH'` confirms `/run/current-system/sw/bin` is present
  via `/etc/profile` → `/etc/set-environment`.
- The fix works because `_run_bash(login=True)` sources `shell_init_files`
  when building the session snapshot, and every subsequent command sources
  the snapshot.

## Test runner note

`scripts/run_tests.sh` probes `.venv` first, which may exist as a stripped
install without pip/pytest. Install pytest into both venvs:

```bash
# .venv has no pip — use uv
uv pip install --python .venv/bin/python pytest pytest-asyncio pytest-timeout
# venv has pip
venv/bin/pip install pytest pytest-asyncio pytest-timeout
```

Then the canonical runner works:
`bash scripts/run_tests.sh tests/tools/test_browser_homebrew_paths.py -q`

## Research findings

- PR #17047 (NousResearch/hermes-agent) addressed NixOS `extraPackages` by
  using per-user profiles (`/etc/profiles/per-user/hermes/bin`), which
  relies on the same PATH setup from `/etc/set-environment`.
- The Hermes FAQ documents `terminal.shell_init_files` as the solution for
  "Terminal commands say node: command not found" under systemd/minimal
  shells.
- NixOS Discourse has multiple threads about why `/bin` doesn't symlink to
  `/run/current-system/sw/bin` — it's a deliberate non-FHS design choice.
